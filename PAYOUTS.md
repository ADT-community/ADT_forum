# Contribution & Payout Policy (DRAFT)

> **Draft for discussion.** Nothing here is a promise of payment yet. Final terms depend on the legal structure (see "Open questions") and will be agreed with contributors before any project starts earning.

## Principles

- **Transparent:** contributions, revenue and payouts are published per project.
- **Fair:** pay reflects real work: code, design, docs, reviews, testing, community and hardware work.
- **Simple:** contributors can check their own points at any time.
- **Accessible:** payouts go through methods that work across Africa (mobile money, bank transfer, and others).

## Revenue split (proposed)

For each project, money it earns (revenue, grants, prizes) is split:

| Share | Goes to |
|------:|---------|
| 60% | Contributor pool for that project, split by points |
| 25% | Project costs (hosting, hardware, legal, payment fees) |
| 15% | ADT common fund (new projects, shared infrastructure) |

The percentages are a starting point for discussion.

## Contribution points (proposed)

Points are recorded from GitHub activity and approved by the project maintainers each month.

| Contribution | Points |
|---|---:|
| Merged pull request, small (docs, fixes) | 1–3 |
| Merged pull request, medium feature | 5–10 |
| Merged pull request, major feature | 15–30 |
| Code review that leads to changes | 1–2 |
| Design work accepted into the project | 3–15 |
| Hardware prototype, test or build log | 5–30 |
| Community: support, moderation, events | 1–5 per month |

Maintainers set the exact size of each task **before** work starts, using issue labels such as `points:5`, so there are no surprises.

## Payout cycle

1. At the end of each month, maintainers publish a points table in the project repo.
2. Contributors have 7 days to dispute.
3. The contributor pool is paid out by share of points for that period.
4. Payouts below a minimum amount roll over to the next month.

## Open questions

- **Legal entity:** who holds the money and signs contracts? Options include a for-profit company, a cooperative, or a fiscal host such as Open Collective. If the Africa Deep Tech Foundation is a nonprofit, the profit side may need its own entity. Get legal advice before taking revenue.
- **Payment rails:** Flutterwave, Paystack, M-Pesa, Wise, and others. Coverage and fees vary by country.
- **Taxes and contracts:** contributors may need a simple contributor agreement.
- **Before revenue:** how to reward early contributors before a project earns anything, for example points that carry forward or a share of grants.
